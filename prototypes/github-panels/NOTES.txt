Recommendations, in implementation order
1. Reduce the detail header. Keep repository, title, branch and chat navigation;
   move secondary actions into a menu. The mock header occupies about 150 CSS px,
   versus about 223 CSS px in the existing 2x comments screenshot. Title wrapping
   can increase this in narrower layouts.
2. Give each comment a quiet author header and contained body. Show review outcome
   as a semantic badge, keep timestamps secondary, and place timestamps on their
   own row when narrow. Markdown already renders in the current implementation;
   improve its typography and spacing rather than replacing the parser. Mocks
   exercise bold, italics, links, quotes, inline code, fenced code and task lists.
3. Use two-line PR rows, with PR number/repository and a labelled CI state beneath
   the title. This improves title visibility and removes color-only CI indicators.
4. Group checks by Failed, Running, Passed and Other. Keep failure and running
   groups visible together, with collapsible passed/skipped/cancelled groups.
5. Give existing file diffs a dedicated Files tab instead of a footer disclosure.

Proposal boundaries
Sample Markdown is expanded to demonstrate formatting. PR detail content is
illustrative; checks change with the selected sample PR, while description,
conversation and files reuse the same fixture. Files navigation, action menus,
latest-review summary and request-changes action are proposals. Check durations
and failure excerpts would need additional data. Inline code threads remain a
GitHub link, matching current coverage. Controls are local previews only.

Open the prototype
Serve the repository root with: python3 -m http.server 8765 --bind 0.0.0.0
Then visit: http://localhost:8765/prototypes/github-panels/
Available URL parameters: view=overview|comments|checks|files,
pr=42|88|17, width=wide|split|panel.
Use the theme button and layout selector for other presentations. Fonts, colors
and theme foundations are loaded from the repository; no external assets.
