# Reconcile Worktrees

Audit evidence before deleting anything. Treat UI badges such as “uncommitted” and “unmerged” as hints: ignored build artifacts can inflate dirty counts, while squash merges and stacked PRs can make merged work look unique.

## Workflow

1. Read repository instructions such as `AGENTS.md` before acting.
2. Resolve the repository and exact worktrees in scope. Map branch names from screenshots to `git worktree list --porcelain`; do not guess paths.
3. Refresh the comparison ref with `git fetch --prune origin` when network access is allowed. Explain that it changes Git metadata and may require approval. Otherwise, say that remote results may be stale.
4. Run the bundled read-only inventory:

   ```bash
   node "$SKILL_DIR/scripts/audit-worktrees.mjs" --repo /absolute/repo/path
   ```

   The helper auto-detects the remote default, `origin/main`, `origin/master`, `main`, or `master`. Override with `--base <ref>`. Add repeated `--path /absolute/worktree/path` arguments to restrict the audit. The invoked-skill context gives the absolute skill directory; substitute it for `$SKILL_DIR`. If `node` is unavailable, gather the same evidence with the Git commands below.

5. Classify committed work, uncommitted work, and generated artifacts separately.
6. Report exact cleanup targets, estimated bytes, recovery paths, and retained branch refs before destructive work.
7. Perform only authorized cleanup, then rerun the inventory and report the actual remaining state.

## Classify Committed Work

- Run `git rev-list --left-right --count <base>...HEAD` and `git cherry <base> HEAD` when the helper is unavailable.
- A `-` from `git cherry` means an equivalent patch exists upstream.
- A `+` does **not** prove work is unmerged. Squash merges, rebases, merge commits, and PRs stacked on non-main bases commonly produce `+`.
- For each `+` branch, look up its PR by exact head branch through the connected GitHub app when available. Confirm state, merged status, base, and merge time. Use local `gh` only when connector coverage is insufficient.
- If no PR exists, inspect branch-only commits and compare their behavior with current base. Preserve the branch ref unless the user separately asks to delete it.

## Classify Uncommitted Work

- Inspect status, staged and unstaged diffs, untracked contents, and timestamps where useful.
- Compare suspected work with current base using `git show <base>:<path>`, `rg`, and history. A small old diff may already be implemented elsewhere.
- Treat regenerated screenshots, formatter-only changes, dead unreferenced helpers, and duplicate fixes as disposable only after verification.
- Treat user-authored source, documents, credentials, local configuration, and unclear untracked files as valuable until proven otherwise.
- Do not commit merely to make a worktree clean. Commit only coherent, wanted work after appropriate tests.

## Clean Generated Artifacts

- Consider only exact reproducible targets such as top-level `node_modules`, `dist`, `dist-test`, `coverage`, and task-specific temp output.
- Verify every target with `git check-ignore`. A familiar directory name alone is insufficient.
- Display absolute paths and sizes before deletion. Never target a repository root, home directory, broad glob, or unresolved variable.
- Remove exact validated paths. Never use `git clean -fdX`; it can erase ignored local configuration and credentials.
- Never follow symlinks. Explain that removing an untracked `node_modules` symlink deletes only the link, then verify its target remains.
- Exclude the current and obviously active worktrees unless the user places them in scope.
- Explain that deleted generated bytes are recreated with the repository’s documented install, build, or test commands.

## Close Worktrees

Recommend closure only when the checkout is inactive and in scope, committed work is merged/equivalent/superseded or retained by a branch ref, uncommitted work is absent or explicitly disposable, and no process is using it.

Obtain explicit confirmation before `git worktree remove --force` discards any dirty worktree. Prefer ordinary `git worktree remove` for clean trees. Preserve local branches by default. Treat branch deletion as a separate destructive phase requiring a separate request and fresh verification.

Never remove the primary checkout, current checkout, or an unresolved path. After removal, verify with `git worktree list --porcelain` and `git worktree prune --dry-run`; prune only if requested or clearly needed.

## Report

Lead with the number audited, cleaned, and closed; bytes reclaimed; merged/equivalent branches; changes committed, preserved, discarded, or unresolved; and branch refs retained. Do not claim closure, merge status, or reclaimed space without post-action verification.
