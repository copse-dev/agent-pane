Privacy Policy

Last updated: June 2025

Your data stays on your machine. Copse is an offline-first desktop app. It doesn't send your code, prompts, or conversations to any server unless you explicitly choose to use a cloud model provider.

The Short Version

  • No cloud by default. Copse only connects to the internet when you configure a cloud model (Anthropic, OpenAI) or an LM Studio server on another machine.
  • No telemetry. No analytics, no crash reporting, no usage data collection. We don't know how often you use the app or what you work on.
  • No accounts. There's no signup, no login, no user identifier.
  • Your API keys stay local. They're stored in your machine's settings and never transmitted to Copse's servers — because Copse doesn't have any.

What Copse Does with Your Data

On-device processing (default)

When you use a local model (e.g. via LM Studio), everything happens on your machine. Your prompts, your code, your conversations — all stay local. No data leaves your computer.

Cloud model providers (optional)

If you configure a cloud model, your prompts and conversation history are sent directly to that provider's API (Anthropic, OpenAI, etc.). This is handled by the app's main process talking directly to the provider's servers — Copse itself never receives, stores, or intermediates your data.

The provider's own privacy policy applies to that data. Copse has no control over what they store or how they use it.

MCP servers (optional)

If you connect MCP servers, those servers may make network requests. Copse does not intercept, log, or store data flowing through MCP servers. You configure and approve each server individually.

Local storage

Copse stores minimal data locally on your machine:

  • Settings and configuration (model URLs, API key references, UI preferences)
  • Conversation history (stored locally, encrypted at rest if you enable it)
  • Project metadata (open folders, recent files)
  • LM Studio model listings (cached locally for performance)

None of this data is transmitted to any external server unless you explicitly configure a cloud model or MCP server that does so.

What Copse Does Not Do

No analytics or telemetry

Copse includes no analytics, crash reporting, usage tracking, or telemetry of any kind. We don't know:

  • How often you use the app
  • What projects you're working on
  • What prompts you send
  • What models you use
  • Whether the app crashes

Your usage is completely private.

No data collection

Copse does not collect, transmit, or store any data on external servers. There are no servers operated by Copse that receive user data. The only network connections the app makes are:

  • Direct connections to cloud model APIs you configure (Anthropic, OpenAI, etc.)
  • Connections to LM Studio on your local network (if configured)
  • Connections to MCP servers you configure (if any)

No third-party SDKs

Copse contains no third-party analytics SDKs, crash reporters, or tracking libraries. Every network request originates from the app's own code and goes only to destinations you explicitly configure.

Permissions

Copse requests only the permissions needed for its features:

  • File system access — Required to read and write your project files
  • Network access — Only used when you configure cloud models or MCP servers. Local mode requires no network access.
  • Shell access — Only when you approve a command. macOS seatbelt sandbox provides additional containment.
  • Clipboard access — Optional, for copying content between the editor and chat

Security

Copse is designed with security as a core principle:

  • API keys are stored locally and encrypted at rest
  • Shell commands run through approval prompts and a macOS seatbelt sandbox
  • Package installs are detected and routed through Socket Firewall with scripts disabled
  • MCP servers require per-server approval before spawning
  • All data stays on your machine unless you explicitly configure cloud providers
